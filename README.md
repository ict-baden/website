# ICT Baden – website

The new website of **ICT Baden GmbH** (Karlsruhe-Durlach): consulting and custom software development
("Getting Things Done") plus the company's own software products for industry, laboratories and IT.
It replaces the old frameset-style site at https://ict-baden.de and adds a product catalogue generated
from the internal project list.

- **Preview:** https://ictbaden.netgetvpn.de (docker01, Cloudflare tunnel, `noindex`)
- **Stack:** [Astro](https://astro.build) 7 (static output), plain CSS with design tokens, a few small
  vanilla scripts, self-hosted fonts. No cookies, no tracking, no external requests.
- **Language:** the site is German; code comments are German, this README is English.

> [!IMPORTANT]
> **Legal note – „Vor dem Livegang auf ict-baden.de rechtlich prüfen“.** The privacy policy
> (`src/pages/datenschutz.astro`) was rewritten for the new static site (old Facebook/Google+/LinkedIn/cookie
> sections removed, server logs and Cloudflare delivery described). It has not been reviewed by a lawyer.
> The imprint data is copied verbatim from the old site.

## Products: where the data comes from

The catalogue is generated from the private repository `ict-baden/ict-baden-projekte` and the product
repositories. Nothing from those repositories is linked or published except the fields listed below.

### Product selection

Only the products listed in `"veroeffentlicht"` in `scripts/public-overrides.json` appear on the website – this is
the one place that decides it (project ids from `projekte.json`). Today these are the seven products being
released: `vitrine` (Vitrine), `qr-scanner` (Lupe), `enterprisebrowser` (Pforte), `industrialkeyboard`
(Industrial Keyboard), `haertungs-check` (Riegel), `freigaben-berechtigungen` (Zutritt) and `labeldesigner`
(Plakette). Ideas and other projects in `projekte.json` stay internal. `scripts/check-products.mjs` (and therefore
CI) fails unless `products.json` contains exactly these ids and every product has a page in
`src/data/produktseiten/`.

To publish another product: add its id to `"veroeffentlicht"`, write `src/data/produktseiten/<id>.ts` (German and
English, every claim backed by the product README – see the header comment of the existing files), add curated
media to `scripts/product-media.json`, run the sync, `npm run icons` and `npm run brand -- --only <slug>`. To remove
one: take it out of the list, run the sync and add a 301 (renamed) or 410 (gone) for its slug in `deploy/nginx.conf`.

The product lines of the website are set in `"linien"` (same file); lines without a product are dropped
automatically.

```bash
node scripts/sync-products.mjs <path-to-ict-baden-projekte> [<folder-with-product-repos> …]
# e.g. local clones next to each other plus a folder with further clones:
node scripts/sync-products.mjs ../ict-baden-projekte ../product-repos
npm run icons        # colour pairs, product icons, README table
npm run brand        # Open Graph images (needs Chromium/Chrome)
```

Product repositories are looked up (case-insensitively, by the repository name from `projekte.json`) in every
folder given and always next to `ict-baden-projekte` (e.g. `../lupe`, `../zutritt`, `../vitrine`); the first hit
wins. To get the clones: `gh repo clone ict-baden/<repo> <dir> -- --depth 1`. The script writes
`src/data/products.json`, `src/styles/product-colors.css` and `public/media/produkte/`; all are committed, so the
build never needs access to the private repositories. A product whose repository is missing locally keeps the
images of the previous run.

**Published per product:** display name, kind (e.g. "BACnet-Explorer"), product line, status, version, the
short `text`, and from `notizen/<id>.md` only the sections *Problem* (as „Ausgangslage“), *Was es ersetzt*
(only if approved, see below) and *Umfang v1*. Products with a repository additionally get the product name
from the README (`<sub><b>Name</b> ·` footer, `# Name` or the alt text of the hero image), the logo
(`docs/assets/logo.svg`; for the Android apps `docs/images/logo.png` or the Play Store icon of the app),
screenshots (light and dark, WebP in 800/1600 px) and – for Vitrine – the demo animation (animated WebP with a
still frame for `prefers-reduced-motion`). Screenshots are found in `docs/assets/screenshots/`, `docs/assets/`
(`<name>-light.png` + `<name>-dark.png`) and `docs/images/` (Android apps, light only, shown as phones).

**Never published:** `repo`, `naechstes`, `von`, the note sections *Technik*, *Offene Punkte*, *Verlauf* and any
other section, file paths, names of people, internal remarks. `scripts/lib/public-guard.mjs` scans the generated
JSON for names from the project repo, repository references, file names/paths, internal numbers and work notes
and aborts the sync (and the CI) if anything slips through.

**Status mapping:** `fertig` → „Verfügbar“, `fast-fertig` → „Vorabversion“ (+ version), `angefangen` →
„In Entwicklung“, `idee` → „Geplant“.

**Editorial rules** live in `scripts/public-overrides.json` (each with a reason):
- *Was es ersetzt* is published only where `"ersetzt": true` is set – i.e. a neutral comparison without value
  judgements about named third-party products. New products therefore start without that section.
- sentences/blocks can be dropped (`dropSentences`, `dropBlocks`, `dropItems`) or corrected (`textReplace`),
  e.g. Vitrine's log is „manipulationserkennend“ (as its README says), not „manipulationssicher“.
- a *Problem* section that only repeats the short text is dropped automatically; `"problem": false` or
  `"umfang": false` drop a section explicitly (the seven product pages use curated sections from
  `src/data/produktseiten/` instead of the note sections).
- where `projekte.json` is out of date, a product can be corrected from its README: `name` (Riegel, Plakette),
  `text`, `status`, `version`, `linie` and `repo` (only used to find README and images, never published).
- **Third-party product names and comparisons** („Alternative zu …“, „Nachbau“, names such as ZebraDesigner,
  Transparent Screen Lock, HardeningKitty … – `COMPETITOR_PATTERNS` in `scripts/lib/public-guard.mjs`) are rejected in
  every field of `products.json` unless the product has `"ersetzt": true` (the sync and `check:products`).
- **Comparison sections (decision 2026-10-21, on):** every product page has a factual „Umstieg von … / Alternative zu
  …“ section with one or two FAQ questions (`alternatives` in `src/data/produktseiten/<id>.ts`, type `Comparison`):
  comparative advertising is allowed when objective, verifiable and not disparaging (§ 6 UWG), naming another
  product to describe ours is allowed (§ 23 MarkenG). Only facts about our product, no „besser als“, no logos, no
  price or quality claims about the other product, and a trademark notice that names every third-party name.
  `check:seo` enforces it on the built pages: third-party names only inside the section (`data-vergleich`) and its FAQ
  questions, never in title, description, H1, the rest of the page, `SoftwareApplication` or `keywords`; every name
  appears in the notice (`data-marken`); no „besser als“. **The lawyer's review is still open** (see „Going live“);
  to switch a section off, set `approved: false`.

**Curated media** live in `scripts/product-media.json` (key = repository name): German tagline, kind (the
category that goes into the H1 and title, e.g. „Transparente Bildschirmsperre für Windows“), highlights, facts,
which screenshots to use with German and English titles/captions/alt texts (taken from the product READMEs and
UIs) and a descriptive file name (`"file"`, e.g. `vitrine-transparente-bildschirmsperre` →
`vitrine-transparente-bildschirmsperre-light-1600.webp`). Alt texts start with product and category and stay under
about 150 characters; details go into the caption. Repositories without an entry still work: the logo is used and
screenshots are picked up automatically with a generic alt text. Banners are off by default (they repeat the
name and claim the page already shows, and some are in English); `"banner": true` enables one. The sync also
records the date of the last commit of each product repository (`updated`): it is shown as „Stand“ on the page
and used as `lastmod` in the sitemap and `dateModified` in the JSON-LD.

**Real assets** (state of the last sync): all seven products have their README name, their own icon, real
screenshots (Vitrine: the real application with sample data; Pforte and Industrial Keyboard: rendered from the app
UI) and German and English texts on the site. Every screenshot exists as WebP and AVIF (`scripts/make-avif.mjs`, run
by the sync); `ThemeImage.astro` offers AVIF first with WebP as fallback.

**Products without screenshots** get generated cover art in the style of their product line (locked cell grid for
OT, barcode with scan line, …) – reproducible from the slug, drawn on graphite and tinted with the product's colour
pair.

### Product pages

Every product has a landing page in German (`/produkte/<slug>/`) and English (`/en/products/<slug>/`), built by
`src/components/product/ProductLanding.astro` from `products.json` and `src/data/produktseiten/<id>.ts`:

- H1 = name + category, a first paragraph that answers „what is it, for whom, platform, licence“ in one or two
  plain sentences (search engines and AI answers quote it), sections per search intent with descriptive H2s (the
  running numbers are a CSS counter, not part of the heading text), features, screenshots, system requirements,
  honest limits, FAQ (questions from the keyword research, plus the comparison questions), related products,
  trademark note. Breadcrumb: Start › Produkte (`/produkte/`) › product.
- **Synonyms without a keyword list:** the common synonyms and search terms (`aka` in `src/data/produktseiten/<id>.ts`)
  are not shown as a list – Google's spam policies count blocks of target terms as keyword stuffing. Each term appears
  naturally at least once in the lead, a section or the FAQ and goes into the JSON-LD as `keywords`; `check:seo` fails
  if a keyword is missing from the visible text.
- `<title>` and meta description per language – **one rule in `src/data/serp.json`, enforced by `check:seo` for every
  page:** title at most 580 px wide in the search result (estimated with Arial 20 px, the width table is in the same
  file), „ | ICT Baden“ only where it still fits (`seoTitle`); description 110–155 characters, main statement first.
  `hreflang` de/en/x-default both ways; `og:type` `website`; `og:image` per product and language
  (`public/og/produkte/<slug>.jpg`, `public/og/en/produkte/<slug>.jpg`) with `og:image:alt`.
- JSON-LD as one `@graph`: Organization, WebSite, WebPage, SoftwareApplication (name, applicationCategory,
  applicationSubCategory = category, `keywords` = synonyms, operatingSystem, licence MIT, `isAccessibleForFree`,
  publisher; `offers` with price 0 EUR and `softwareVersion` only for released products; `downloadUrl`/`sameAs` only
  when the download is public), FAQPage (same questions as on the page) and BreadcrumbList. No ratings – there are
  none. **One SoftwareApplication `@id` per language page** (`<page URL>#software`): each page describes the product
  completely in its language (own url, OG image, description, keywords, feature list); one shared `@id` would give the
  same node two different urls, images and descriptions. The language versions are linked by `hreflang`; Organization
  (`/#organization`, text in the page's language), WebSite and the portfolio video (`/#video`) are one node each.
- **Download flag – one line per product:** `download.public` in `src/data/produktseiten/<id>.ts` is `false` for all
  seven, because the repositories are private and GitHub would answer every download link with a 404. Then the
  status everywhere (cards, product page, OG image, llms.txt) is „Vorabversion <version>“ with „Veröffentlichung in
  Kürze“, the page offers an enquiry instead of a download, says „kostenlos unter der MIT-Lizenz“ instead of „Open
  Source“, the app privacy page has no source link, and the JSON-LD has no `offers`, `downloadUrl`, `codeRepository`,
  `sameAs` or `softwareVersion`. When a repository goes public, set `public: true`: the status from `products.json`
  („Verfügbar“), the download button (`url` = the tagged release, `…/releases/latest`), the source link, „Open
  Source“, `offers` (price 0 EUR), `downloadUrl`, `codeRepository` and `softwareVersion` appear by themselves. Set
  `play` once the app is on Google Play. Regenerate the OG images afterwards (`npm run brand -- --only <slug>`), they
  show the status.
- Every product page links the privacy policy of its app (`src/data/app-datenschutz.ts`, matched by project id).

### Brand assets

The brand comes from `ict-baden/richtlinien` (`marke/`, still marked as a draft there): the logo (gold field, red
diagonal bar over the right side only, black wordmark „ICT“ + „baden“) and the short mark (field with „ICT“, bar
over the top-right corner). The drafts are kept unchanged in `src/assets/brand/richtlinien/`. Their text is set
in Segoe UI (weight 800/600), which only Windows has; `src/assets/brand/marke.json` therefore holds the text as
outlines, exactly as Windows renders the drafts (Segoe UI Black for 800, Semibold for 600, letter spacing as in
the drafts), so the mark looks the same on every device. The logo carries its own field and works unchanged on
light and dark backgrounds (`src/components/Logo.astro`, variant `zeichen` for the short mark).

`npm run brand` regenerates `favicon.svg/.ico` (short mark), `apple-touch-icon.png` (full yellow square),
`public/brand/icon-32/180/192/512.png`, `icon-maskable-512.png`, `ict-baden-logo.svg`, `ict-baden-zeichen.svg` and
all Open Graph images (`public/og/…`; `--no-og` skips them, `--only a,b` renders single ones). The OG template is
`src/components/OgCard.astro`, built only with `OG_TEMPLATES=1` and photographed with Chromium: the site image is
the logo field itself (yellow, red bar, black text), product images are ICT black with the product icon and a
screenshot on the product's colour pair.

### Product icons

Every product has an app icon in the style of `marke/app-icon-vorlage.svg` from the guidelines: 32 × 32 grid,
28 × 28 tile at (2, 2) with radius 7, top-to-bottom gradient of the product's own colour pair, white symbol
(stroke 2–2.6, round caps, at most two or three shapes, legible at 16 px), no text, no third-party logos.

- Products whose repository has its own icon in this style keep it (Lupe, Zutritt, Vitrine, Riegel, Plakette; Pforte
  and Industrial Keyboard with their Android app icons). Raster app icons are fitted into the template geometry
  by the sync (tile 28/32 with a 2/32 margin, corner radius 7/32), so they match the generated icons in size.
- All others get a generated icon: `scripts/product-icons.mjs` defines colour pair and symbol per project id,
  `npm run icons` writes `src/assets/product-icons/<id>.svg`, `src/styles/product-colors.css` and the table below,

  unchanged (same paths, scaled into the tile), set in the template – white on its own gradient. The repositories

- Colour pairs were chosen on a grid of 13 hues × 3 lightness levels so that products of the same line differ

## Configuration and staging

| Variable | Default | Effect |
|---|---|---|
| `SITE_URL` | `https://ictbaden.netgetvpn.de` | canonical URLs, sitemap, Open Graph |
| `SITE_STAGING` | `1` | `1`: `<meta name="robots" content="noindex">`, `robots.txt` disallows everything, preview bar, Cloudflare section in the privacy policy, nginx sends `X-Robots-Tag: noindex`. `0`: live – `robots.txt` allows everything and names the main search and AI crawlers explicitly. |

image `:latest`) and the live version (`SITE_STAGING=0`, `SITE_URL=https://ict-baden.de`, image `:live`). The live
build takes `INDEXNOW_KEY`, `GOOGLE_SITE_VERIFICATION` and `BING_SITE_VERIFICATION` from the repository variables
(Settings › Secrets and variables › Actions › Variables) – none of them is secret, they end up on the public site.

## Search engines and AI search

What the site does for Google, Bing and AI answer engines (ChatGPT search, Perplexity, Claude, Google AI Overviews):

- One landing page per product and language whose H1, title, first sentence and FAQ use the words people search
  for („transparente Bildschirmsperre“, „Barcode-Scanner für den PC“, „NTFS-Berechtigungen auslesen“, „Kiosk-Browser
  für Zebra-Geräte“, …), synonyms in the running text and FAQ (no keyword lists), no hidden text; a product overview
  per language (`/produkte/`, `/en/products/`) with all products as cards.
- Static HTML only – every crawler gets the full content without JavaScript.
- Structured data (see Product pages), Organization + LocalBusiness (address, areaServed, contact in German and
  English, `sameAs` the public GitHub organisation; no opening hours or coordinates – there is no source for them;
  texts in the language of the page), WebSite and the portfolio video as VideoObject on the home page (data from
  `src/config.ts` only); the product overviews carry an ItemList.
- No automatic language redirect: a German page shows a small „also available in English →“ bar when the browser
  language is not German; the visitor's choice is remembered (`localStorage` `lang`, `lang-hint`).
- `sitemap.xml` with `xhtml:link` hreflang alternates and `lastmod` (product pages: last commit of the product
  repository); `/llms.txt` and `/llms-full.txt` from the same data, German and English (each product with its English
  page, lead and FAQ; the download status is stated once per product).
- Descriptive file names and alt texts for screenshots; decorative images (icons next to a heading, the hero
  collage, cover art) keep `alt=""`/`aria-hidden`.
- Factual comparison sections with third-party names, checked by `check:seo` (see Editorial rules).

### Going live – checklist

The live image `ghcr.io/ict-baden/website:live` is built and probed by the CI on every push to `main` (no
`X-Robots-Tag`, no `noindex`, `robots.txt` without `Disallow: /`, canonical, hreflang and sitemap on
`https://ict-baden.de`, all redirects and 410s). Nothing runs on ict-baden.de until someone starts it.

**State of the domain today** (checked 2026-10-21 with `dig` and `curl`): the zone `ict-baden.de` is **not** on
Cloudflare but at GoDaddy (nameservers `ns35.domaincontrol.com`, `ns36.domaincontrol.com`). The old site runs on a
GoDaddy Apache at `92.205.238.62`; `www.ict-baden.de` is a CNAME to the apex, and `https://www.ict-baden.de` fails
(the certificate has no `www`). http is not redirected to https, there is no HSTS. Mail: MX for Google Workspace
(`aspmx.l.google.com` priority 1, `alt1`/`alt2.aspmx.l.google.com` 5, `alt3`/`alt4.aspmx.l.google.com` 10) plus
`mail.ict-baden.de` (priority 50, A `46.163.106.222`). TXT: `MS=…` and `google-site-verification=…`; no SPF, no DMARC.
The alias domains `ict-baden.com`, `ictbaden.de`, `it-baden.de`, `itbaden.de` and `itbaden.org` (also at GoDaddy, some
with their own MX) serve the old site with 200.

1. **People first:** legal review of the privacy policies (website and the seven apps), the imprint (company name
   „ICT Baden GmbH“), the comparison sections with their trademark notices (incl. the factual claim about CodeTwo on

   e-motional and Softros use as product names) and the product names; then remove the IMPORTANT note at the top.
2. **Repository variables** (optional, not secret): `INDEXNOW_KEY` (e.g. `uuidgen | tr -d -`), and – only if Search
   Console/Bing are verified by meta tag instead of DNS – `GOOGLE_SITE_VERIFICATION`, `BING_SITE_VERIFICATION`. Then
   re-run the CI on `main` so that `:live` contains them.
3. **Start the live container on docker01:** `SITE_MODE=live deploy/deploy.sh` (copies
   `deploy/docker-compose.live.yml` to `/srv/docker/ict-baden.de`, starts `ictbaden-live` on 192.168.4.6:8018 with
   the tunnel label `cf.tunnel.hostname=ict-baden.de`). The preview keeps running (`ictbaden-web`, noindex); after
   the go-live put it behind Cloudflare Access (`cf.tunnel.access`) or stop it, so that no externally linked preview
   URL shows up as „indexed, though blocked by robots.txt“. `deploy.sh` refuses to put a preview image on ict-baden.de
   or the live image on the preview (tag and image label are checked before switching).
4. **Move the zone to Cloudflare (owner of the domain), before anything points to the tunnel:** export the zone file
   from GoDaddy (DNS › Export) as a reference. Add the site `ict-baden.de` to Cloudflare and re-create **all** records
   that the import misses – the apex A record (still `92.205.238.62` until step 5), `www`, all six MX records with
   their priorities, `mail.ict-baden.de` (A, **DNS only**, never proxied), both TXT records (`MS=…`,
   `google-site-verification=…`) and every other record in the export (SRV, CNAMEs such as `autodiscover`). Compare
   the two zones line by line, then switch the nameservers at the registrar (GoDaddy › Domain › Nameservers) to the two
   Cloudflare nameservers and wait until Cloudflare shows the zone as active (only then can the tunnel label from step
   3 route `ict-baden.de`; if the hostname was not created by itself, add it in step 5). **Check mail right afterwards:**
   `dig MX ict-baden.de @1.1.1.1` shows the same six entries, a test mail from outside reaches the Google Workspace
   mailbox and one to an address on `mail.ict-baden.de` arrives, the Search Console property is still verified.
   (SPF/DMARC do not exist today; adding them is a separate decision for whoever runs the mail.) If the zone has to
   stay at GoDaddy, Cloudflare can only front the site through a partial (CNAME) setup, which needs the Business plan
   and cannot cover the apex `ict-baden.de` from GoDaddy DNS – so moving the zone is the way.
5. **Cloudflare / DNS (now on Cloudflare):** point `ict-baden.de` and `www.ict-baden.de` to the tunnel (the label
   above, or a public hostname in the tunnel config → `http://192.168.4.6:8018`); SSL/TLS „Full“, **„Always Use
   HTTPS“ on** (http → https 301 – behind the tunnel nginx only sees http and cannot do it); `www` → apex 301 (Redirect
   Rule; nginx does it as well). HSTS comes from nginx (`max-age=31536000`, no `includeSubDomains`; leave Cloudflare's
   own HSTS setting off). **Security › Bots:** „Block AI bots“ off, AI Crawl Control „allow“, „Manage robots.txt“ off
   (the site has its own), Bot Fight Mode must not challenge verified bots. Keep the Cloudflare paragraph in the
   privacy policy (shown because `SITE_CDN=cloudflare`).
6. **Alias domains → 301 to `https://ict-baden.de/`:** `ict-baden.com`, `ictbaden.de`, `it-baden.de`, `itbaden.de`,
   `itbaden.org` each redirect permanently, with path, to the main address – either at their DNS host (GoDaddy
   forwarding: permanent 301 to `https://ict-baden.de/`) or, if a domain is moved to Cloudflare as well, with a
   Redirect Rule (or Bulk Redirects) `301 → https://ict-baden.de${path}`. Their MX records stay untouched. A hostname
   that is routed to the tunnel instead gets the same 301 from nginx (every host other than `ict-baden.de`).
7. **Check from outside**, then submit to IndexNow: `SITE_MODE=live INDEXNOW_KEY=<key> deploy/deploy.sh` again (it
   checks `X-Robots-Tag`, `robots.txt`, canonical and a redirect, then submits all sitemap URLs). By hand:

## Deployment (docker01, automatic)

Every push to `main` deploys itself:

1. CI (`.github/workflows/ci.yml`) builds the site twice (preview and live) and runs the product, link, HTML, SEO,
   live (`scripts/check-live.mjs`) and accessibility checks;
2. it builds `deploy/Dockerfile` twice (nginx 1.27 + `dist/` or `dist-live/` + `deploy/nginx.conf`, the `# STAGING`
   lines only in the preview, the `# LIVE` lines only in the live image, `/version.txt` = commit), starts each image
   once on the runner and probes it (`scripts/probe-image.sh`: pages incl. the paths the apps link and the product
   overviews, redirects, 410, www → apex, HSTS, noindex in the preview and none in the live image, and in the live
   image every other host – alias domains, an IP – → 301 to `https://ict-baden.de`, `/health` on every host) – on pull
   requests too;
3. on `main` it pushes `ghcr.io/ict-baden/website:latest` and `:<commit>` (preview) and `:live` and `:live-<commit>`;
4. Watchtower on docker01 checks every 5 minutes and restarts `ictbaden-web` (and, after the go-live, `ictbaden-live`)
   with the new image.

Which commit is live: <https://ictbaden.netgetvpn.de/version.txt>. A failed check stops the push, so the running
version stays. Manual pull or rollback (Git Bash on Windows works; needs ssh access to docker01):

```bash
deploy/deploy.sh                     # pull :latest now instead of waiting for Watchtower
IMAGE_TAG=9597d8b deploy/deploy.sh   # roll back to a commit (Watchtower then stays on that tag)
IMAGE_TAG=latest deploy/deploy.sh    # follow main again
SITE_MODE=live deploy/deploy.sh      # live version on ict-baden.de (see "Going live"); IMAGE_TAG=live-<commit> rolls back
```

Server layout (`DEPLOY_DIR`, default `/srv/docker/ictbaden.netgetvpn.de`): `docker-compose.yml` with
`ghcr.io/ict-baden/website:${IMAGE_TAG:-latest}`, 192.168.4.6:8017 → 80, restart unless-stopped, labels
`cf.tunnel.hostname=ictbaden.netgetvpn.de`, `cf.tunnel.service`, `cf.tunnel.access=none`; optionally `.env` with a
pinned `IMAGE_TAG`. The image package is public (it only contains the public website), so docker01 needs no
registry credentials.

The CI probe also checks that the redirects and the `X-Robots-Tag` header behave as configured before it pushes.

nginx serves static files with gzip, long-lived caching for hashed assets (`/_astro/`), security headers and a
strict Content-Security-Policy (`script-src 'self'; style-src 'self'` – the site has no inline scripts or styles),
HSTS (`max-age=31536000`, deliberately without `includeSubDomains`: the subdomains such as `mail.ict-baden.de` are not
ours to pin), `/health`, and 301 redirects from the old URLs. The live image answers every host other than
`ict-baden.de` – `www`, the alias domains, a bare IP – with a 301 to `https://ict-baden.de$request_uri` (`/health`
excepted, for the Docker and deploy health checks); http → https is Cloudflare's job (behind the tunnel nginx only
sees http). The access log format deliberately leaves out forwarded client addresses.

## Design

- **Colours** (from the guidelines): Baden-Gelb `#FFD200` as surface and highlight (hero band, buttons with black
  text, contact band, selected filters, icon tiles, selection), ICT-Schwarz `#111111` for text and the dark bands,
  Baden-Rot `#E2001A` sparingly (the diagonal bar, link underlines, small numbers). Light mode: warm white
  `#faf9f5` / ink `#111111`; dark mode: `#111111` / `#f4f3ef`, yellow becomes the accent for links, icons and focus,
  and the hero shows the yellow field with the red bar on the right only. Yellow is never used as text on light
  backgrounds and red never as text on yellow (text red is `#c8001a` light / `#ff5c6a` dark). Each product has its own
  colour pair (see Product icons). All text colours meet WCAG 2.2 AA (checked with axe in both themes).
- **Diagonal bar:** the motif of the logo (slope 1 : 2) is used on the right side only – hero, page heads, contact
  band, the "all products" tile – never as a coat-of-arms diagonal across a whole field.
- **Type:** Archivo Variable (headlines, width 104–108 %) and Inter Variable (text), both self-hosted via
  @fontsource, Latin subsets preloaded.
- **Light/dark:** `light-dark()` tokens follow the system; the toggle stores an explicit choice in
  `localStorage` (`theme`), applied by a tiny blocking script before first paint (no flash).
- **Motion:** CSS-only entrance animations, scroll-driven reveals and cross-document view transitions – all
  disabled with `prefers-reduced-motion`.
